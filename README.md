# Deep Understanding Protocol

一个把「理解」这个不可观察的内部状态，替换为一组**可被外部审查的产出物**的认知质量闸门。

不是回答模板。是闸门——跳层即输出降级为复述，等于没处理。

## 这是什么

`deep-understanding-protocol` 对输入的知识强制执行七层加工：

```
深编码 → 结构化入库 → 迁移 → 必要困难 → 元认知校准 → 自适应修正 → 生成
```

输出固定六段格式：一句话抽象 / 原子节点 / 迁移示例 / 反例与失效边界 / 确定度标注 / 一个新问题或新连接。

## 核心设计

| 设计 | 意图 |
|---|---|
| 用「产出物是否齐全」代理「是否真懂」 | 内部状态不可判定，故导出外部代理信号 |
| 六段固定格式 | 格式即**审查接口**，让读者能快速看出哪一层是空的 |
| 确定度四档标注 | 把**证据强度**与**结论强度**解耦 |
| 强制跨域迁移 | 阻断「能复述」冒充「能迁移」 |
| 强制回写修正 | 唯一的自我纠错入口 |

## v2.1 修正了什么

本仓库打包的版本在 v2 原文基础上**内嵌了对其自身的元层自审**。自审发现 1 处内部逻辑矛盾 + 4 处设计缺陷，均在 `SKILL.md` 中以 `⛔ v2.1 修正` 标出：

| # | 缺陷 | 修正 |
|---|---|---|
| 1 | **内部硬矛盾**：第 2 层说"无法内省判断自己懂不懂"，第 4 层却要求"主动定位自身弱点构造反例" | 反例**优先取自外部料源**；自造反例须标低置信度 |
| 2 | **第 6 层在单轮必然空转**，硬性"不得跳层"会制造伪产出 | 无外部新信息时**显式声明不执行**，不编造修正记录 |
| 3 | **"不回读"混淆记忆测试与理解测试** | 只作加工纪律，不作理解判据 |
| 4 | **"七层耗时"是计算错误** | 成本在**输出篇幅**，不在层数 |
| 5 | **`[已证实]` 被当作免检标签** | 须写实测方式；注意形式合规会降低读者警惕 |

**新增机制——终止条件**：原文是单向加压的元协议，缺收敛判据（可无限质疑任何结论）。v2.1 引入**双阈值闭环**（外部核验通过率 / 新增反例产出率），让协议能收束。

**新增子清单——「我其实没懂的」**：确定度标的是证据强度，不标是否真懂。两者独立——一个人可以拿着强证据说出自己并不理解的话。

## 用法

协议**只服务于理解与建模**，不用于交付型任务。

| 场景 | 是否上协议 |
|---|---|
| 推送一个观点/概念/结论，期望真正吃透 | ✅ 上 |
| 「深度分析」「按七层处理」「真正理解而不是复述」 | ✅ 上 |
| 写报告、查数据、生成文件、调试代码 | ❌ 直接干活 |
| 一句话能答完的 | ❌ 直接答 |
| 「帮我看看这个能不能买」 | ⚠️ 先给判断，协议作背景 |

**判据**：用户是在**给你知识让你吃透**，还是在**要你干活**？

**简单门槛**：若该输入用三句话就说完且不会引起误解，不要上协议。

## 为什么把缺陷也打包进来

修正不是删改原文，而是**标注「这里原文如此、且这里有已知问题、应如何处理」**。

理由有三：
1. **抹掉发现过程，等于抹掉最有价值的部分。** 缺陷的推导过程本身就是一份七层加工示范。
2. **协议自身的诚实度是它的可信度来源。** 一份不敢记录自身失效边界的协议，不值得作为认知闸门使用。
3. **修正会引入新缺陷。** v2.1 的双阈值仍需自标定、三条新连接仍需跨例检验。留痕使得下一轮修正有据可依。

## 已知未验证项

第 6 层判决规则的候选方案（保护带思路 / 样本量门槛）来自外部理论，**未在本协议语境下验证可用**。三条新增连接均附可检验预测，但**预测本身尚未执行**。
